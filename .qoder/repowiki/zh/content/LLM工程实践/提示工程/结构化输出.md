## 核心组件
- 结构化输出与约束解码（理论与实践）
  - 三类方法：提示工程、原生结构化输出 API、约束解码

- 前端 Playground
  - schema 驱动表单、结果区域渲染、交互式调试

## 详细组件分析

### JSON 校验器（后端）
- 输入：payload（JSON 文本）、required_fields（可选，逗号分隔）
- 处理流程：
  - 去除 Markdown 代码围栏
  - JSON 解析与错误定位（行列号）
  - 字段类型统计与顶层类型标注
  - 必填字段缺失检查
  - 结果以表格、键值对、JSON 原始数据块展示
- 输出：summary（结论）、blocks（结构化结果块）

```mermaid
flowchart TD
Start(["开始"]) --> Clean["去除代码围栏"]
Clean --> Parse{"尝试解析 JSON"}
Parse --> |失败| ReportErr["返回解析错误与定位信息"]
Parse --> |成功| TypeStats["统计字段类型与顶层类型"]
TypeStats --> Required{"是否提供必填字段"}
Required --> |否| Done["生成结论与结果块"]
Required --> |是| CheckReq["检查缺失字段"]
CheckReq --> HasMissing{"是否存在缺失"}
HasMissing --> |是| Warn["标记缺失字段并生成结论"]
HasMissing --> |否| Ok["标记合法并生成结论"]
Warn --> Done
Ok --> Done
ReportErr --> End(["结束"])
Done --> End
```

## 性能考虑
- 约束解码通常更快：缩小下一 token 搜索空间、对强制 token 可跳过生成
- 本地校验开销极低：仅 JSON 解析与字符串处理
- 前端校验适合快速迭代：无需调用后端，即时反馈
- 运行时格式校验：轻量级，避免下游解析失败导致的昂贵回滚

## 故障排查指南
- JSON 解析失败
  - 前端：提示错误类型、消息与定位（行列号），建议检查引号/逗号/括号配对
  - 后端：提供行/列定位，便于快速定位问题
- Markdown 代码围栏
  - 前端/后端均支持去除围栏，避免解析干扰
- 必填字段缺失
  - 明确列出缺失字段，辅助补齐 schema 或提示用户修正
- 格式校验拦截
  - JSON 解析失败、代码块未闭合、空输出、期望 JSON 但非 JSON
  - 通过 GuardrailResult 的 details 与 confidence 辅助决策

### 设计严格输出格式模板的步骤
- 字段定义
  - 明确必填字段与可选字段
  - 为每个字段指定类型（字符串、数字、布尔、数组、对象）
  - 对复杂字段给出嵌套 schema 或示例
- 数据类型验证
  - 数字范围、枚举集合、正则表达式
  - 空值处理（允许 null 或拒绝）
- 嵌套结构处理
  - 递归 schema 使用 CFG（如 XGrammar）或展平策略
  - 字段顺序：推理在前，答案在后，避免过早承诺
- 输出质量控制
  - 合规率目标 100%
  - 语义有效性（LLM 评判）
  - 字段覆盖率、延迟 p50/p99
- 错误恢复
  - 格式校验失败时的降级策略（回退模型、拒绝服务）
  - 重试上限与指数退避
